# Проверка очереди действий и сроков

9 октября 2026. Реализация по [спецификации](../superpowers/specs/2026-10-09-home-action-queue-design.md), выполнена как выбранная пользователем итерация Ralph.

## Техническая проверка

- Полный backend test и bootJar: 156 тестов, без ошибок/пропусков. Новые HTTP-сценарии — 6/6; до реализации route возвращал 404 и проверки падали.
- Frontend: 55 unit-проверок, typecheck и production build. Тесты фиксируют приоритет CTA, частичные страницы, слияние без повторов, stale identity/generation, очистку при потере доступа и отдельный `422 EMAIL_UNCONFIRMED`.
- Фактический `private, no-store` подтверждён HTTP-тестом; описание OpenAPI дополнено реальным статусом 422. Queue-read не извлекает контакты или приватные заметки.
- Замороженные assessment/matching/interview и dependency manifests проверяются по исходным SHA-256. Отдельный LSP-сервер и linter не настроены. CLI `lsp_diagnostics_directory` с backend tsc дал 0 ошибок и предупреждений; также выполнены свежие Kotlin/TypeScript compiler checks, regression tests и проверка whitespace diff.

## Сквозные сценарии

Изолированный loopback-стенд с новой синтетической QA-базой; outbox отключён. Реальных участников и внешний стенд эта проверка не затрагивает.

1. Из 10 принятых приглашений один шаг выполнен: очередь содержит 9 активных записей. Первая страница — 5+, Enter загружает все 9 без повторов. Собственные действия идут первыми; даты, отсутствующий срок и просрочка показаны отдельно.
2. Ссылка открывает конкретное обсуждение с тем же action/deadline. При отсутствии pending invitations собственный шаг становится основной рекомендацией. Добавленное ожидающее приглашение возвращает главный CTA к приглашениям; начатая оценка сохраняет высший приоритет в regression test.
3. На 1280 и 390 px нет горизонтального переполнения. Очередь стоит перед KPI; первая мобильная дата заканчивается на 551 px у кандидата и 584 px у работодателя в viewport 844 px. Два промежуточных расположения не прошли визуальную проверку, затем исправлены. Итоговый субъективный визуальный verdict — PASS 94; это не pixel metric или измерение конверсии.
4. Скрытие профиля оставляет разрешённые общие шаги, но имя становится null в API и исчезает из строк компании при возвращении к вкладке. Используется нейтральный ID обсуждения.
5. Потеря подтверждения email у QA-компании во время загрузки следующей страницы даёт `422 EMAIL_UNCONFIRMED`: ранее загруженные строки исчезают и доступен повтор. Другие 422 остаются обычными ошибками частичной страницы.
6. Отзыв исходного разрешения исключает старые шаги из очередей обеих ролей. Новый отличающийся grant принятого приглашения показывает только один новый шаг; прежние записи не открываются повторно. Профиль в этом сценарии остаётся скрытым. Кандидат читает архив старого диалога.

## Ревью и границы

Независимый архитектор дал CLEAR по коду и фактическим артефактам после исправления несоответствия 403/422. Отдельный async-review выявил поздний denial старой личности; теперь он игнорируется по identity/generation. Standard ai-slop-cleaner ограничен изменёнными файлами и завершается повторной регрессией; подробности и финальные логи находятся в исключённом из Git local/ralph-iteration-2026-10-09/.

Текущий company context следует существующему выбору active membership; переключатель компаний не добавлен. Очередь живая, не фиксированный snapshot: изменения между страницами могут требовать обновления. Нет обещания мгновенного realtime-отзыва. Управляемые задержки сетевых ответов проверены state-regressions и анализом wiring, не полноценным mounted-hook chaos-тестом. Сохраняется предупреждение о frontend chunk больше 500 kB. Технические и синтетические результаты не доказывают качество реального найма, человеческую валидность грейда, полный WCAG-аудит или эксплуатационную готовность.
