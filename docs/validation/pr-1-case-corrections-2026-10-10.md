## Итоговое поведение

- Trust Score, неподтверждённые verified/status/signals и вымышленные95/96 убраны из сервера и UI. Верификация работодателя не добавлена как обязательный MVP.
- Публикация передаёт полный DTO потребности; сервер проверяет обязательные поля, владельца/активность и соответствие актуальным условиям. Ошибки формы400, устаревшие условия409VERSION_CONFLICT. Нет зарплаты по умолчанию. Двойное нажатие блокируется; неуспешный повтор того же намерения использует прежний ключ.
- Запись вакансии/отклика/статуса/отзыва проходит MutationService. Повтор одного ключа/тела не создаёт дубль; отличное тело конфликтует. Конкурентные отклики сохраняют уникальность.
- PDF требует текущее согласие на обработку до разбора. Должность/грейд без факта остаются пустыми, Senior/стаж не превращаются в Middle. Извлечённые поля предлагаются для явного подтверждения. Ожидаемая ошибка PDF400INVALID_FILE сохраняет причину для диагностики; неожиданные сбои не маскируются.
- Самостоятельный отклик передаёт явно выбранные включённые каналы только компании вакансии. V10 создаёт отдельное разрешение; вымышленные принятые приглашения/глобальные grants не создаются. V9 не изменена. Публичная видимость не отменяет прямой отклик; отзыв обработки закрывает новые чтения личных полей, отдельный отзыв контактов закрывает contact reads. Пустой выбор является корректным состоянием200[]; UI различает его, отзыв и приостановку обработки.
- Контактные чтения сверяют текущие каналы/согласия, владельца и разрешение. Consent version берётся из общего сервиса; batch-проверки под блокировкой сохраняют актуальность и не добавляют per-row N+1 запросы.
- JSON-экспорт профилей использует действующие исходные разрешения после принятых приглашений, только enabled каналы, без account_email fallback, с блокировкой и журналом. Это экспорт JSON, а не реальная интеграция с ATS-провайдером.
- Страница компании больше не зависит от Trust Score; неполная запись с null name рендерится нейтрально и сохраняет обязательность имени. Минимальный отклик после отзыва обработки не приводит к падению клиента.
- OpenAPI и типы клиента описывают фактические endpoints/DTO/errors/headers. Сопроводительные Markdown/PDF и их SHA/размеры согласованы. Конкретные разрешения/отзыв/идемпотентность обозначены решениями проекта, а не буквальными дополнительными требованиями организатора.
