# Главная работодателя: достоверность и независимые блоки

9 октября 2026. Итерация N1 / I01–I02, одобренная после исследования. Реализовано: нижняя граница либо неизвестное число при неполных страницах приглашений и потребностей; loading/error/retry своего блока; очередь, шапка и переходы остаются на экране.

## Изменения

- App.tsx использует существующий pendingInvitationCount, разделяет состояния needs/sent и не показывает старые данные блока после ошибки refetch. Использован существующий workModeName; новые состояния/зависимости не добавлены.
- Stat допускает локальную ошибку с повтором; brand.css переносит сообщение/кнопку внутри этой карточки.
- package.json включает новый SSR-регрессионный файл tests/employer-home.test.mjs в обычный npm test. Тесты рендерят настоящий App с реальным QueryClient; отдельный DOM test framework не нужен.

## Свежие проверки

До реализации: восемь ожидаемых assertion failures из девяти тестов, один baseline pass. После: девять из девяти. Полный npm test: 64 из 64. npm run typecheck, npm run build и git diff --check прошли. Vite сообщает о размере основного JS chunk более 500 kB; разделение bundle не входит в эту итерацию. Отдельный linter не настроен, его успешный запуск не заявляется.

Браузерный стенд использовал production build и loopback-сервис с синтетическими ответами. При медленном /needs очередь видима. При ошибках needs/sent остальные готовые блоки доступны. Показаны unknown при pending только за первой страницей и ≥2 при неполном положительном результате. Кнопка повтора needs: один дополнительный needs-запрос, без sent-запроса. Клавиатурный повтор sent: один sent-запрос, без needs-запроса. Точный ноль показан только после исчерпанного успешного ответа.

Первый screenshot на 390 px обнаружил overflow 442 px. Локальный перенос исправил его: scrollWidth/clientWidth 390/390. Desktop: 1280/1280. Независимый source review не нашёл блокирующих замечаний, включая финальное правило CSS.
