# План N2: восстановление глубины очереди

**Цель:** при безопасном обновлении очереди сохранить глубину, которую пользователь уже раскрыл, используя только свежие авторизованные данные.

## Реализация

1. Сначала добавить регрессионные тесты: обновление после двух страниц, отсутствие старых строк в свежем снимке и ограничение API в 100 записей.
2. Хранить только скаляр намеренной глубины в состоянии очереди, чтобы очистка строк не сбрасывала её; сохранять её при обычной ошибке и сбрасывать при потере доступа/смене identity.
3. Добавить к запросу глубину/лимит и отправлять refresh с начала списка; обычная загрузка продолжения остаётся по свежему cursor.
4. Для старой глубины свыше 100 показать честный частичный результат и оставить существующее продолжение доступным.
5. Вернуть фокус только к той же свежей ссылке, если пользователь не перевёл фокус на другой элемент; очищать цель при выходе из очереди и смене identity, искать ссылку внутри очереди.
6. Проверить полный frontend test suite, typecheck и итоговый diff.

## Решения и стоп-условие

Выбран один запрос на refresh, ограниченный backend-контрактом `1..100`; запросы по одному на страницу создавали бы серию изменений списка и расширяли окно гонок. Старые строки не склеиваются с новым ответом. При ошибке остаётся состояние ошибки без защищённых данных. Завершить после зелёных frontend-тестов/typecheck и документирования фактических ограничений; продуктовую пользу не утверждать.
