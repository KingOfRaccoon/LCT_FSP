# Достоверная и устойчивая главная работодателя

Одобрено пользователем «Вперед» после исследования следующих итераций. Эта первая итерация реализует I01/I02 и N1 из docs/research/2026-10-09-next-improvements.md. Следующие итерации очереди и входа в воронку остаются отдельными шагами.

## Поведение

Главная всегда показывает шапку, очередь действий и быстрые переходы. Запрос потребностей не блокирует счётчик приглашений и наоборот. Ошибка/загрузка локальны; кнопка повтора запускает только запрос своего блока. Независимость не означает доступность неизвестных или запрещённых данных.

Успешная исчерпанная страница приглашений даёт точное число pending. Если next_cursor есть и на странице есть pending, показываем ≥N и «Не менее N · есть ещё приглашения». Если next_cursor есть, но pending нет, показываем — и «Есть ещё приглашения · число пока неизвестно». Loading/error тоже не равны нулю. Переход ко всем приглашениям остаётся доступным. Используется существующий pendingInvitationCount; новых агрегатов и загрузки всего списка нет.

API потребностей тоже имеет пагинацию (по умолчанию 50). Активные потребности на неполной странице обозначаются аналогично: ≥N либо —, без ложного общего количества. Если на неполной странице нет рабочих потребностей, сообщаем «На этой странице потребностей в работе нет» и предлагаем открыть список, а не создать первую потребность.

Ошибочный refetch с сохранёнными данными не показывает старый счётчик как актуальный. Истекшая авторизация не раскрывает кешированные данные локального блока. UI очереди и original-grant/identity/generation/consent проверки остаются существующими.

## Подход

Выбран минимальный вариант: существующие useQuery, условный рендер каждого блока и уже проверенная семантика lower-bound. Серверный агрегат потребовал бы нового контракта; загрузка всех страниц ради KPI добавила бы ненужную работу. Они не входят в первый вариант.

## Проверка

Регрессионные тесты рендерят настоящий App на маршруте / с QueryClientProvider и синтетическим работодателем. Vite уже установлен и преобразует TSX для SSR без новых зависимостей. Проверяем неполный ноль, неполное положительное число и точный ноль; независимость loading/error; ошибку refetch с прежними данными; неполную страницу потребностей. SSR доказывает рендер, а интерактивный локальный smoke отдельно проверяет текущую очередь и кнопки повтора. Проверки людей/рост конверсии не заявляются.

Существующие frontend-тесты, typecheck/build и diff --check обязательны. Backend/контракты/политики не изменяются. Прежние грязные файлы сохраняются; коммит/push этой итерацией не выполняется.
