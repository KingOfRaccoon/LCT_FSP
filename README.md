# ФСП · Таланты

Платформа подбора ИТ-специалистов для Федерации спортивного программирования. Кандидат заполняет профиль и проходит оценку, работодатель описывает потребность или выбирает кандидатов из банка и отправляет предложение с условиями и зарплатой. Кандидат решает, принять ли предложение и открыть ли контакты.

В `main` находится обзор проекта. Исходный код, конфигурация запуска и подробная документация находятся в ветке [`prototype`](https://github.com/KingOfRaccoon/LCT_FSP/tree/prototype). Все команды ниже выполняются из её корня.

Проект работает как прототип с демонстрационными данными. Текущий каталог оценки — Backend Python, уровни junior и middle. Банк заданий не прошёл содержательное экспертное ревью и человеческую валидацию; выдача реальных грейдов заблокирована.

## Возможности

### Кандидат

- Регистрация, вход и подтверждение электронной почты.
- Профиль с опытом, проектами, навыками, форматом работы и зарплатными ожиданиями.
- Импорт текстового PDF-резюме с проверкой черновика и выбором полей перед сохранением; экспорт профиля в PDF.
- Тестирование, автосохранение ответов, история попыток и портфель подтверждений с источниками и версиями методики.
- Тренировочные вопросы с разбором и Python-песочница с примерами и текстовым черновиком. Тренировка не сохраняет результат на сервере и не влияет на грейд; код в песочнице не исполняется и не проверяется.
- Просмотр вакансий и отклики, получение прямых приглашений от компаний.
- Принятие или отклонение предложения, переписка после принятия и просмотр следующего шага найма.
- Выполнение коротких адресных задач и отдельное согласие на передачу решения компании.
- Управление видимостью профиля, предварительный просмотр публичных сведений, журнал открытия контактов и отзыв доступа.

### Работодатель

- Профиль компании и заявка на проверку реквизитов и представителя.
- Потребности в специалистах: категория, навыки, формат работы, город, занятость и условия предложения.
- Подбор по потребности, банк кандидатов, фильтры, шорт-листы и сравнение профилей.
- Объяснение соответствия: подтверждённые и заявленные навыки, неизвестные сведения, вопросы для интервью.
- Подсказки по доступным кандидатам и защищённая сводка зарплатных ожиданий при достаточном объёме данных.
- Публикация вакансий и работа с откликами.
- Приглашения с обязательной зарплатой, сохранёнными условиями и необязательным планом этапов найма.
- Переписка, общий следующий шаг, сроки, приватные заметки и этапы работы с кандидатом.
- Короткие задачи с автоматической проверкой однозначного ответа либо оценкой по объявленной рубрике.

### Методист и оператор

- Мастерская методиста: источники, черновики заданий, ревью версий, экспериментальные наблюдения, экспорт формы и отдельного закрытого ключа.
- Очередь проверки компаний: решение, основание, срок действия и устаревание результата при изменении реквизитов.
- Панель операций: состояние БД, почтовой очереди, worker и HTTP-запросов.
- Необязательная серверная запись камеры и экрана во время оценки, отдельное согласие и ручное решение оператора. В обычном локальном запуске запись выключена.

Мастерская и операции требуют отдельных серверных разрешений. Регистрация работодателя не выдаёт эти права.

## Оценка, подбор и доступ к данным

Тест содержит 12 заданий и 24 оцениваемых ответа по четырём блокам: Python, HTTP/API, SQL/транзакции и надёжность. На попытку отводится 30 минут. Текущий порог — 18 из 24 баллов и минимум 3 из 6 в каждом блоке. Повтор того же уровня доступен через 24 часа; для смены подтверждённого грейда действует интервал 30 дней. Время контролирует сервер, перезагрузка страницы его не продлевает.

Подбор разделяет кандидатов на группы «подтверждены», «нужно уточнение» и «нужно подтверждение». Явное несоответствие обязательному условию исключает профиль; неизвестные сведения остаются неизвестными. Заявленный навык не считается подтверждённым тестом. Достижения ФСП используются как дополнительное свидетельство внутри подтверждённой категории и не повышают грейд.

Контакты открываются по отдельному разрешению кандидата. Приглашение хранит снимок условий и сведений компании; их изменение требует новой версии предложения. Отзыв разрешения закрывает связанный доступ компании. Передача решения короткой задачи регулируется отдельным согласием; результат такой задачи не меняет грейд платформы.

При включённой серверной записи попытка ожидает решения оператора до публикации результата. События браузера и экспериментальные сигналы не устанавливают нарушение автоматически. Запись не заменяет проверку качества банка заданий.

## Архитектура и стек

| Компонент | Реализация |
| --- | --- |
| Веб-интерфейс | React 19.2, TypeScript 5.9, Vite 8, React Router 7, TanStack Query 5 |
| API | Kotlin 2.2.20, Spring Boot 3.5.9, JDK 21 |
| Хранение | PostgreSQL 17, JDBC, миграции Flyway |
| Почтовая доставка | Отдельный worker, очередь outbox, SMTP; локально Mailpit |
| Публикация веб-интерфейса | Nginx, проксирование `/api` в backend |
| Мониторинг | Необязательный overlay с Prometheus и Grafana |
| Исследовательские инструменты | Python: ревью банка, пилот, слепая проверка подбора, проверка восстановления БД |

Браузер обращается к Nginx, который отдаёт интерфейс и проксирует запросы в API. API хранит данные в PostgreSQL. Worker читает почтовую очередь из той же БД и отправляет письма через SMTP. Медиа серверной записи хранятся отдельно от веб-каталога.

## Быстрый запуск с Docker

Нужны Git и запущенный Docker с Compose v2. JDK и Node на хосте для этого способа не требуются. При первой сборке нужен доступ к образам и репозиториям зависимостей.

```bash
git clone --branch prototype --single-branch https://github.com/KingOfRaccoon/LCT_FSP.git
cd LCT_FSP
docker compose up -d --build
docker compose ps
```

| Адрес | Назначение |
| --- | --- |
| [http://localhost:8080](http://localhost:8080) | Приложение |
| [http://localhost:8025](http://localhost:8025) | Mailpit: просмотр локальных писем |
| [http://localhost:8080/api/v1/health](http://localhost:8080/api/v1/health) | Проверка процесса API |
| [http://localhost:8080/api/v1/ready](http://localhost:8080/api/v1/ready) | Готовность API и соединения с БД |

Compose запускает `db`, `api`, `worker`, `web` и `mailpit`. API применяет миграции и создаёт демонстрационные аккаунты. База и медиа используют именованные тома. Порты веб-интерфейса и почты опубликованы только на localhost.

Для запуска с Docker файл `.env` необязателен: демонстрационные значения заданы в Compose. `.env.example` предназначен для нативной разработки и содержит `PUBLIC_ORIGIN=http://localhost:5173`. Если используете `.env` с Docker, задайте `PUBLIC_ORIGIN=http://localhost:8080`.

Проверка готовности и просмотр логов:

```bash
curl --fail http://localhost:8080/api/v1/ready
docker compose logs --tail=100 api worker web
```

Остановка с сохранением данных:

```bash
docker compose down
```

### Демонстрационные аккаунты

Общий пароль: `DemoPassword123!`.

| Логин | Роль |
| --- | --- |
| `candidate@example.test` | Кандидат |
| `employer@example.test` | Работодатель |
| `other-employer@example.test` | Второй работодатель для проверки разграничения доступа |
| `methodist@example.test` | Методист |
| `operator@example.test` | Оператор |

Аккаунты создаются при включённых demo mode и seed. Все исходные профили и результаты синтетические. Для просмотра кандидата в банке нужно принять текущие согласия; для открытия контактов — принять приглашение и дать соответствующее разрешение.

### Сценарий знакомства

1. Войти кандидатом, проверить профиль и открыть настройки согласий.
2. Пройти демонстрационную оценку или изучить существующие подтверждения.
3. В отдельном браузерном профиле войти работодателем, создать потребность и посмотреть подбор либо банк.
4. Подготовить и отправить приглашение с зарплатой и условиями.
5. Вернуться к кандидату, принять предложение и открыть переписку.
6. Проверить следующий шаг и отзыв контактного доступа.

## Разработка без контейнеров приложения

Нужны JDK 21, Node.js 22.12+ или 24 LTS, npm и PostgreSQL 17. Для Python-утилит нужен Python 3.11+. Backend собирается через Gradle Wrapper; отдельная установка Gradle не нужна.

Ниже PostgreSQL и Mailpit запускаются в Docker, API и интерфейс — на хосте. Перед этим остановите основной Compose, чтобы освободить порт Mailpit. Команды создания контейнеров выполняются один раз:

```bash
docker run -d --name fsp-dev-db \
  -p 127.0.0.1:55432:5432 \
  -e POSTGRES_DB=fsp_dev \
  -e POSTGRES_USER=fsp \
  -e POSTGRES_PASSWORD=fsp_demo \
  -v fsp-dev-data:/var/lib/postgresql/data \
  postgres:17-alpine

docker run -d --name fsp-dev-mail \
  -p 127.0.0.1:1025:1025 \
  -p 127.0.0.1:8025:8025 \
  axllent/mailpit:v1.29
```

Дождитесь готовности PostgreSQL и создайте отдельную тестовую базу:

```bash
docker exec fsp-dev-db pg_isready -U fsp -d fsp_dev
# После успешной проверки, один раз:
docker exec fsp-dev-db createdb -U fsp fsp_test
```

Для последующих запусков используйте `docker start fsp-dev-db fsp-dev-mail`. Если PostgreSQL уже установлен, вместо этих контейнеров создайте базы `fsp_dev` и `fsp_test` с пользователем `fsp`, паролем `fsp_demo` и доступом на `127.0.0.1:55432`.

Скопируйте `.env.example` в `.env`. Spring не загружает этот файл автоматически: экспортируйте переменные в каждом терминале, где запускается backend или worker. Задайте `JAVA_HOME` на установленный JDK 21; на macOS скрипт также ищет его через `java_home`. Команды ниже рассчитаны на Bash/Zsh; на Windows используйте WSL.

Первый терминал, API:

```bash
cp .env.example .env
set -a
. ./.env
set +a
./scripts/backend-local.sh
```

Второй терминал, почтовый worker:

```bash
set -a
. ./.env
set +a
./scripts/backend-local.sh --spring.main.web-application-type=none --fsp.outbox-enabled=true --fsp.seed-demo=false
```

Третий терминал, интерфейс:

```bash
npm --prefix frontend ci
npm --prefix frontend run dev -- --host 127.0.0.1
```

Откройте [http://localhost:5173](http://localhost:5173). Vite проксирует `/api` на `http://localhost:8000`. Письма доступны в Mailpit на порту 8025; без worker письма останутся в очереди. Для работы с существующим аккаунтом backend можно запустить с `--fsp.seed-demo=false`.

## Настройки

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL`, `DATABASE_USERNAME`, `DATABASE_PASSWORD` | Соединение API и worker с PostgreSQL |
| `PUBLIC_ORIGIN` | Адрес интерфейса для ссылок и проверки origin: 8080 в Docker, 5173 в разработке |
| `SESSION_SECRET`, `SESSION_COOKIE_SECURE` | Секрет сессии и передача cookie только через HTTPS |
| `FSP_DEMO_MODE` | Демонстрационный режим |
| `FSP_SEED_DEMO` | Создание demo-данных; локальный скрипт и Compose API также задают seed аргументом запуска |
| `SMTP_HOST`, `SMTP_PORT` | SMTP для почтового worker |
| `COMPANY_VERIFICATION_PROVIDER`, `DADATA_TOKEN` | Ручная проверка компаний либо необязательная сверка через DaData |
| `FSP_METRICS_TOKEN_FILE` | Файл токена защищённого чтения метрик |
| `FSP_PROCTORING_ENABLED`, `FSP_PROCTORING_MEDIA_ROOT` | Включение записи оценки и закрытый каталог медиа |

При `COMPANY_VERIFICATION_PROVIDER=manual` внешний реестр не нужен. Для сверки через DaData задайте `dadata` и серверный токен. Без токена автоматическая сверка недоступна, ручная очередь сохраняется. Статус проверки компании не подтверждает юридические полномочия представителя.

Подключение Prometheus/Grafana описано в [инструкции мониторинга](https://github.com/KingOfRaccoon/LCT_FSP/blob/prototype/docs/operations-monitoring.md). HTTPS, хранилище, согласие и включение записи — в [инструкции прокторинга](https://github.com/KingOfRaccoon/LCT_FSP/blob/prototype/docs/proctoring-deployment.md). Для `PUBLIC_ORIGIN=https://hirundo-team.space` launcher API отдельно включает запись и secure cookie; этот запуск отличается от локального Compose.

## Проверки и сборка

Backend-тесты используют отдельную БД `fsp_test` на `127.0.0.1:55432`, пользователь `fsp`, пароль `fsp_demo`. Создайте её перед запуском. Команды выполняются из корня `prototype`:

```bash
./backend/gradlew -p backend --no-daemon --max-workers=1 test bootJar
npm --prefix frontend ci
npm --prefix frontend test
npm --prefix frontend run typecheck
npm --prefix frontend run build
python3 -m unittest discover -s scripts/tests
```

После изменения OpenAPI обновите TypeScript-схему:

```bash
npm --prefix frontend run types:api
```

Backend JAR создаётся в `backend/build/libs/fsp-talent-backend-0.1.0.jar`, интерфейс — в `frontend/dist`. Dockerfile backend собирает JAR без тестов, поэтому контейнерная сборка не заменяет тестовый прогон.

## Структура репозитория

```text
backend/             API, доменная логика, миграции и Kotlin-тесты
frontend/            React-интерфейс, API-клиент, стили и тесты
docs/contracts/      OpenAPI, правила подбора и шаблон интервью
docs/assessment/     Банк заданий, методика и запись выпуска
infra/               Dockerfile, Nginx, HTTPS и мониторинг
scripts/             Локальный запуск, исследовательские и служебные утилиты
submission/          Презентация, сопроводительная документация и демо-видео
compose.yml          Локальный демонстрационный запуск
compose.monitoring.yml  Дополнительный мониторинг
local/               Локальные данные и артефакты; каталог исключён из Git
```

Python-утилиты готовят экспертные пакеты и формы assessment-пилота, анализируют ответы, экспортируют наборы для слепого ревью подбора и проверяют восстановление локальной БД. Входные банки, ключи, ответы и отчёты хранятся в `local/`. Подготовленный пакет не означает проведённое исследование.

## Ограничения и эксплуатация

- Демонстрационные результаты не доказывают профессиональный уровень кандидата или эффективность найма. В записи выпуска банка `content_review` и `human_validation` равны `not_performed`, `real_grade_release_ready` — `false`.
- Каталог ограничен одной специализацией и двумя уровнями. Сравнимость форм и пороги требуют проверки на реальных данных.
- Интеграция достижений ФСП демонстрационная. Рабочая интеграция с реестром ФСП или ATS не заявлена.
- Импорт резюме рассчитан на текстовые PDF; скан без текстового слоя требует отдельного распознавания.
- Тексты согласий, процессы обработки данных и сроки хранения требуют утверждения оператором.
- `compose.yml` предназначен для локального demo. Для production предусмотрены профиль Spring и `.env.production.example`: собственные секреты, HTTPS origin, secure cookie, выключенные demo/seed и отдельное применение миграций. Production guard проверяет эти условия при запуске.
- Публичный ingress, права runtime-пользователя БД, резервное копирование, наблюдение и удаление данных настраиваются для конкретной среды.
